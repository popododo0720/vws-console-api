# Rules: full statements

`AGENTS.md` lists every rule in one line with its main check. This file has
the full statement of each rule and every test, lint or CI job that enforces
it. When you add or change a rule, change its row here and its line in
`AGENTS.md` in the same pull request, and add its check.

## Rules

Configured Proxmox subnets with mode `static` or an empty mode allocate the
lowest free IPv4 address in the inclusive `ip_range`, or the usable CIDR
hosts excluding the gateway. Every allocation reads every QEMU VM's live
`ipconfig0` across all pools, including templates, and requires cluster-wide
`VM.Audit`; an unreadable config fails closed. Before cloning, RunInstances
counts unconfigured pending launch markers against free capacity and returns
`InsufficientFreeAddressesInSubnet` without cloning when capacity is exhausted.
If capacity disappears after acceptance, finalize leaves the VM for retry
(failure cleanup belongs to #998).

Every static finalizer pass first CAS-updates the optional 32-hex `ipfence`
launch marker on all eligible unconfigured VMs in managed pools. A locked
pending VM or a failed barrier prevents allocation in that pass. Each barrier
and allocation write rechecks the leader fence. This makes a delayed old
leader's allocation either visible before the barrier or rejected by its
stale per-VM digest; the five-second lease margin alone is not a write fence.
The ordinary finalizer lock serializes allocations within a process without
holding the launch mutex during start waits. Retry keeps a configured VM's
address; no in-memory address cache is authoritative. Describe reads the IPv4
address from `ipconfig0` for both the instance and primary NIC, omitting absent
or DHCP values. Direct and DHCP launch configuration is unchanged. Enforced
by `TestStaticLaunchLowestFreeAndModes`, `TestStaticLaunchExhaustionAndPending`,
`TestStaticLaunchConcurrentAndCrashRetry`,
`TestStaticLaunchLeaderHandoverFencesDelayedWrite`, `TestStaticPrivateIPQuery`,
`TestStaticLaunchRefusesIncompleteInventory`, and
`TestInsufficientFreeAddressesInSubnetWire`.

Only regions with `live_tests: true` interpret the RunInstances user tag
`vws-live-run` as a live run ID. When present, its value must match
`[a-z0-9][a-z0-9-]{0,39}`; invalid values return InvalidParameterValue before
any clone. The clone description already persists the user tags, so a new
backend can recover the run ID after a crash. Finalize adds exactly one
`vws.live.<runid>` to the same digest-CAS config write as the launch replay
tags, without a separate tag write. Same-token retries and resumed finalize
preserve that tag. Regions without live tests treat the key as an ordinary
user tag and write no system live tag. DescribeInstances retains
`vws-live-run` as a user tag, while `vws.live.*` never decodes as one.
Enforced by `TestLaunchLiveRunTags`,
`TestLaunchLiveRunRejectsInvalidBeforeClone` and
`TestLaunchLiveRunResumesFinalize`.

Console usage requires `vws:GetUsage` on `*`, accepts only one `from` and
`to` date with start before exclusive end and at most 366 days, and reads
current allocation from live project pools without PVE or registry writes
or retained snapshots. Failed regions omit allocation and report a fixed
safe error. Enforced by `TestUsageWindowAndAuthorization`,
`TestUsageFailureMetadataAndRegistry`, `TestUsageAPIAllocationReadOnlyAcrossRestart`
and `TestAllocationRequiresPoolVisibility`. The first part excludes AWS
cost and historical RRD data (`docs/usage.md`).

## Adding a long-running action (moved from AGENTS.md)

1. Add the `Action` constant in `internal/resource`, plus its request type
   (`Action` and `Normalize`) and any lifecycle row. `exhaustive` flags a
   switch that misses it. `Actions()` is derived from the constants.
2. Add the method on the backend interface. Implement it in the fake and
   region client and transport it through regionapi; declare regional capabilities.
3. Add the case to `backendtest`.
4. Add a one-line kernel method that calls `mutate`.
5. Add the console route in `handler.mutation`. `TestEveryActionHasARoute` fails until the route is real.
6. Add the query action in `ec2query` when the query protocol has that action.
7. Add an interop test when a second surface can perform the same mutation.

## e2e (moved from AGENTS.md)

`e2e/e2e.py` drives the EC2 Query and S3 entry points with boto3.
`VWS_E2E_BACKEND` is `fake`, `regions` or `proxmox`. `VWS_E2E_CAPS` lists what the backend
can do (`vm`, `eip`, `direct` when `VWS_E2E_DIRECT_SUBNET`, default
`subnet-direct-prod`, is a configured direct network). `VWS_E2E_ACCESS_KEY` and `VWS_E2E_SECRET_KEY` are the
root credentials the SigV4 clients sign with; they default to the public
development values, which real backends refuse, so a live run sets both. A
step that needs a missing capability prints `skipped(reason)` and does not
count as a pass. The run ends with a banner that lists every skip and
`status=PASS|FAIL|INCOMPLETE`. `VWS_E2E_STRICT=1` makes a skip exit 3. CI sets
it, so the fake run cannot lose a step silently.

`cli_identity()` drives the IAM and STS actions through the aws CLI v2 the same
way, and `cli_detach()` drives `aws ec2 detach-volume` (#210). They run `VWS_E2E_AWS_CLI`, or the `aws` on `PATH`, with no profile and no
retries; without one their steps are `skipped(aws-cli not available on this
host)`, so CI, where the runner image has the CLI, fails rather than skips.

```sh
pip install -r e2e/requirements.txt
e2e/run.sh                          # fake backend, started by the script
VWS_E2E_BACKEND=regions VWS_E2E_CAPS=vm,eip \
  VWS_E2E_ACCESS_KEY="$VWS_ACCESS_KEY" VWS_E2E_SECRET_KEY="$VWS_SECRET_KEY" \
  python3 e2e/e2e.py                # endpoints already running
```
